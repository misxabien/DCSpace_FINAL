================================================================================
DC SPACE  ↔  eRoomReserve
Integration Handoff / Connection Guide
================================================================================

Purpose
-------
Connect eRoomReserve room reservations with DC Space event approval in near
real time. When a reservation is approved, rejected, cancelled, or completed
in eRoomReserve, DC Space should receive that update immediately so admins can
validate venues and approve campus events.

This document describes ONLY what eRoomReserve needs to connect TO DC Space
(inbound webhook). Please implement the client/webhook on your side using the
contract below.


================================================================================
1. ENDPOINT
================================================================================

Production URL:
  POST https://dcspace-final.vercel.app/api/integrations/reservation-info

Headers (required):
  Content-Type: application/json
  Authorization: Bearer <SHARED_SECRET>

Notes:
  - Method must be POST.
  - HTTPS only.
  - The shared secret will be provided separately through a secure channel
    (do not commit secrets to git or public docs).
  - Expected auth format is exactly:
      Authorization: Bearer <SHARED_SECRET>


================================================================================
2. WHEN TO CALL (REAL-TIME REQUIREMENT)
================================================================================

Call this endpoint whenever a reservation changes in a way that affects DC
Space event validation, especially on every status transition:

  - approved
  - rejected
  - cancelled
  - completed

Also send an update if room identity/name/capacity changes for an active
reservation.

Preferred model: event-driven webhook (near real-time), not daily batch sync.


================================================================================
3. REQUEST BODY CONTRACT
================================================================================

Required JSON fields:

{
  "reservationId": "ERR-2026-000123",
  "status": "approved",
  "room": {
    "id": "room-dra-hall",
    "name": "DRA HALL",
    "capacity": 200
  },
  "updatedAt": "2026-08-25T06:30:00.000Z",
  "eventId": "68a8bf6e67b17dfa35d6448af"
}

Field reference
---------------
reservationId   (string, required)
  Stable unique reservation ID from eRoomReserve.

status          (string, required)
  Must be one of:
    - "approved"
    - "rejected"
    - "cancelled"
    - "completed"

room.id         (string, required)
  Stable room identifier in eRoomReserve.

room.name       (string, required)
  Human-readable room / venue name.
  DC Space uses this as the event venue/location when linking.

room.capacity   (number, required)
  Non-negative integer/float capacity of the room.
  Used by DC Space for occupancy and crowd analytics.

updatedAt       (string, required)
  ISO-8601 timestamp of the change (UTC preferred), e.g.
  "2026-08-25T06:30:00.000Z"

eventId         (string, optional)
  OR alias: dcSpaceEventId
  DC Space MongoDB event document ID.
  Strongly recommended when known so the reservation links to the correct
  pending event.


================================================================================
4. SUCCESS / ERROR RESPONSES
================================================================================

200 OK
  {
    "ok": true,
    "reservation": {
      "reservationId": "...",
      "status": "approved",
      "room": { "id": "...", "name": "...", "capacity": 200 },
      "eventId": "..."
    }
  }

401 Unauthorized
  Missing/invalid Authorization Bearer token.

400 Bad Request
  Payload failed validation (missing fields, wrong status, bad room shape).

500 Internal Server Error
  DC Space could not store the update.


================================================================================
5. WHAT DC SPACE DOES WITH YOUR UPDATE
================================================================================

On a valid POST, DC Space will:

  1) Upsert the reservation into collection: reservationStatuses
  2) Link / update the related campus event with:
       - reservationId
       - reservationStatus
       - reservationRoomId / reservationRoomName / reservationCapacity
       - location (from room.name when applicable)
  3) Unlock admin "Approve Event" only after room status is
       "approved" or "completed"
  4) Notify DC Space admins when status becomes "approved"


Linking strategy (if eventId is omitted)
----------------------------------------
  1) Prefer events already tagged with the same reservationId
  2) Otherwise attach to a pending event whose venue matches room.name
  3) Best practice: always send eventId when available
