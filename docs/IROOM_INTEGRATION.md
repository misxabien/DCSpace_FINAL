# DC Space ↔ IRoomReserve Integration

This document defines how DC Space shares overlapping data with IRoomReserve (Firebase) so both systems stay connected without merging databases.

## Ownership

| System | Database | Owns |
|---|---|---|
| DC Space | MongoDB | Users, events, registrations, attendance, certificates |
| IRoomReserve | Firebase | Rooms, availability, reservation approval workflow |

DC Space writes reservation **requests** into IRoomReserve Firebase. IRoomReserve writes reservation **status** back to DC Space via webhook.

---

## Firebase collections (IRoomReserve team adds these)

| `course` | string | Course |
| `sourceSystem` | string | Always `"dcspace"` |

## API endpoints

### DC Space → IRoomReserve

**POST** `/api/integrations/iroom/reservations`

Organizer creates/refreshes a reservation for an on-campus event.

Request:
```json
{ "eventId": "674abc..." }
```

Response:
```json
{
  "reservationId": "dcspace-674abc...",
  "status": "pending",
  "openUrl": "https://iroom.example/reserve?...",
  "firebaseConfigured": true
}
```

### IRoomReserve → DC Space

**POST** `/api/integrations/iroom/webhook`

Header: `X-Iroom-Secret: {IROOM_WEBHOOK_SECRET}`

Body:
```json
{
  "reservationId": "dcspace-674abc...",
  "dcSpaceEventId": "674abc...",
  "status": "approved",
  "roomId": "avr-101",
  "roomName": "AVR Room 101",
  "building": "Main Building",
  "approvedBy": "admin@sdca.edu.ph",
  "approvedAt": "2026-08-23T08:00:00.000Z"
}
```

### Read status

**GET** `/api/integrations/iroom/reservations?eventId={id}`

## Environment variables (DC Space `.env`)

```env
IROOM_FIREBASE_PROJECT_ID=
IROOM_FIREBASE_SERVICE_ACCOUNT={"type":"service_account",...}
IROOM_APP_URL=https://your-iroom-app.example/reserve
IROOM_WEBHOOK_SECRET=shared-secret-with-iroom-team
IROOM_USERS_COLLECTION=linkedUsers
IROOM_RESERVATIONS_COLLECTION=reservations
```

If Firebase vars are empty, DC Space still stores reservation links in Mongo and shows status locally. Firebase sync activates once credentials are added.

---

## User flow

1. Organizer creates an **On Campus** event in DC Space.
2. Organizer uploads concept paper and clicks **iRoom Reserve**.
3. DC Space saves the event draft, upserts `linkedUsers` + `reservations` in Firebase.
4. IRoomReserve opens (if `IROOM_APP_URL` is set) for room selection/approval.
5. IRoomReserve approves/rejects and calls the DC Space webhook.
6. DC Space updates `iroomStatus` on the event and shows it on the organizer detail page.
7. If the event is cancelled/postponed in DC Space, the linked reservation is marked `cancelled` in Firebase.

## What not to sync

Keep these in DC Space Mongo only:

- Passwords and auth tokens
- Attendance / RFID logs
- Registrations, invitations, certificates, feedback
- Full base64 media files (use attachment URLs only)
